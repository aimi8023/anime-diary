# 公开追番档案数据流与浏览结构设计

日期：2026-07-29

## 背景

Anime Diary 的公开首页目前由客户端组件在挂载后请求 `/api/anime`，全局搜索组件也会独立请求同一接口。由于搜索组件挂在根布局中，首页、登录页和管理页都会初始化整套公开搜索状态。这会造成重复请求、首屏“加载中”、派生数据不同步，以及存储故障被错误地表现为空内容或客户端异常。

随着 Bangumi 辅助录入和版本化备份已经完成，下一阶段优先把公开首页从“客户端加载的季度卡片列表”升级为“服务端优先的个人追番档案”。本阶段只调整公开页面的数据流和浏览结构，不修改数据模型、存储格式、管理 API、Bangumi 规则或备份机制。

## 目标

- 首页由服务端一次读取数据并输出可用首屏 HTML。
- 移除首页和全局搜索之间的重复数据请求。
- 筛选结果从原始数据与筛选条件派生，不保存第二份可变列表。
- 支持关键词、年份、季度、标签、最低评分和排序组合。
- 将筛选条件同步到 URL，刷新和分享后可以恢复。
- 以年份和季度组织记录，提高长期浏览与回顾效率。
- 点击卡片可查看完整记录详情。
- 明确区分正常空数据、筛选无结果和存储读取失败。
- 保持管理后台、公开 API、Bangumi 录入和备份恢复行为不变。

## 非目标

- 不增加独立番剧详情路由。
- 不增加数据库分页、搜索服务或新的状态管理库。
- 不迁移现有季度命名或历史记录。
- 不重做图片管线、品牌视觉和完整动画系统。
- 不改变 Redis、JSON 存储和备份格式。
- 不在本阶段重构管理后台信息架构。

## 方案选择

采用服务端优先的档案页：

```text
app/page.tsx（Server Component）
  ├─ 服务端读取全部记录
  ├─ 解析并规范化 URL 参数
  ├─ 计算基础统计
  └─ ArchiveBrowser（Client Component）
       ├─ 浏览工具栏
       ├─ URL 同步
       ├─ 筛选、排序与分组
       ├─ 年份/季度档案
       └─ 记录详情对话框
```

保留 `GET /api/anime` 作为公开接口，但首页自身不再依赖该接口。当前记录规模适合一次读取全部数据；后续只有在数据量显著增长时才考虑分页。

## 数据流

1. `app/page.tsx` 在服务端调用现有 `storage.getAll()`。
2. 页面解析 `searchParams`，通过纯函数生成安全的初始筛选条件。
3. 原始记录、初始筛选条件和基础统计作为 props 传给 `ArchiveBrowser`。
4. `ArchiveBrowser` 在首次服务端渲染时使用相同纯函数得到结果，避免带筛选 URL 的页面水合闪烁。
5. 用户修改条件后，客户端在内存中重新筛选、排序和分组，不重新请求数据。
6. 筛选条件通过 `router.replace` 写入 URL，并保持当前滚动位置。

根布局不再持有公开记录和筛选结果。现有 `SearchProvider`、`SearchFilter` 和客户端搜索按钮被移除或替换为指向首页档案区域的普通导航。

## URL 与筛选规则

支持以下查询参数：

| 参数 | 含义 | 规则 |
|---|---|---|
| `q` | 关键词 | 搜索标题、原名、标签和短评，忽略大小写与首尾空白 |
| `year` | 年份 | 四位数字，来自 `season` 前四位 |
| `season` | 季度 | 仅接受 `春`、`夏`、`秋`、`冬` |
| `tag` | 标签 | 逗号分隔；多标签要求记录全部包含 |
| `rating` | 最低评分 | 1–10，按 0.5 步长规范化 |
| `sort` | 季度内排序 | `rating`、`title` 或 `added` |

所有有效条件之间采用 AND 关系。默认排序为 `rating`。非法参数被忽略并使用安全默认值，不导致页面错误。

示例：

```text
/?q=音乐&year=2024&season=夏&tag=治愈,日常&rating=8&sort=rating
```

关键词输入使用约 250 毫秒延迟。筛选更新使用 `router.replace`，避免为每次输入制造浏览器历史。清除全部筛选后 URL 恢复为 `/`。

## 页面信息架构

### 顶部介绍

- 标题“我的追番档案”和简短说明。
- 总记录数、年份跨度和季度数。
- 站点运行计时器保留为辅助信息。
- 管理入口弱化为锁形导航，不成为公开页主要操作。

### 浏览工具栏

桌面端直接展示关键词、年份、季度、标签、最低评分和排序。移动端保留关键词输入与“筛选”入口，其余条件放入底部面板。工具栏下方显示结果数、当前条件和“一键清除”。

### 档案主体

- 年份按新到旧排列。
- 年份内部继续按季度排列。
- 默认展示全部年份。
- 最近年份保持展开，较早年份可折叠。
- 季度继续支持独立折叠。
- 排序只改变季度内卡片顺序，不改变年份和季度的时间顺序。

### 卡片与详情

卡片用于快速浏览，仅突出封面、标题、评分、主要标签和一行短评摘要。点击后打开详情对话框，展示完整短评、集数、原名、开播日期、季度和 Bangumi 链接。

桌面端详情使用侧边面板，移动端使用底部面板。对话框支持 Esc、遮罩关闭、初始焦点和关闭后的焦点恢复。

## 组件边界

```text
components/archive/
  archive-browser.tsx
  archive-hero.tsx
  archive-toolbar.tsx
  active-filters.tsx
  archive-results.tsx
  year-section.tsx
  anime-detail-dialog.tsx
```

- `app/page.tsx`：服务端读取、参数解析入口和故障状态。
- `lib/archive/filter.ts`：参数规范化、筛选、排序、分组和统计纯函数。
- `ArchiveBrowser`：筛选状态、URL 同步和当前详情选择。
- `ArchiveToolbar`：桌面与移动筛选控件。
- `ActiveFilters`：结果数量、当前条件和清除操作。
- `ArchiveResults`：年份、季度和空结果渲染。
- `AnimeDetailDialog`：详情交互与无障碍行为。

现有 `AnimeCard` 与 `SeasonSection` 可以在迁移期间复用视觉样式，但数据组织和交互职责转移到 `archive/` 目录。单个组件只负责一个明确层级，避免重新形成大型页面组件。

## 错误与空状态

- 存储读取失败：显示“暂时无法读取追番记录”和重新加载入口。
- 正常空数据：显示尚未建立档案的空状态。
- 筛选无结果：保留当前条件并提供清除入口。
- 非法 URL 参数：忽略非法值，其余合法条件继续生效。
- 单条可选字段缺失：详情中隐藏对应字段，不影响其他记录。

错误不得被转换成空数组；页面不得因响应结构异常进入永久加载状态。

## 性能与交互约束

- 首页每次服务端请求只读取一次记录数据。
- 筛选、排序和分组使用纯函数与 `useMemo`。
- URL 更新不触发数据重新请求。
- 卡片动画延迟设置上限，不随记录索引无限增长。
- 本阶段继续使用现有封面加载方式，图片优化留到视觉精修阶段。
- 尊重 `prefers-reduced-motion` 的完整规范留到视觉阶段，但新交互不得依赖动画才能理解。

## 测试

### 纯函数

- 标题、原名、标签和短评关键词搜索。
- 年份、季度、标签和最低评分筛选。
- 多标签全部匹配。
- 多条件组合。
- `rating`、`title`、`added` 排序。
- URL 参数解析、规范化和非法值回退。
- 年份与季度分组顺序。
- 输入数组不被修改。

### 页面与组件

- 服务端读取成功、空数据和存储失败。
- 初始查询参数正确反映到控件和结果。
- 修改筛选后 URL 更新且没有重新请求数据。
- 清除全部筛选。
- 桌面和移动筛选入口。
- 打开、关闭详情与焦点恢复。
- 无结果状态。
- 根布局不再初始化全局番剧搜索数据。

### 回归

- 管理后台、Bangumi、备份和存储测试保持通过。
- `GET /api/anime` 行为保持不变。

## 验收标准

- 首次访问首页不再出现客户端“加载中”。
- 首页不存在两个组件分别请求 `/api/anime`。
- 搜索与筛选过程不重新访问服务器。
- 刷新和分享筛选 URL 后状态保持。
- 桌面与移动端均可筛选、清除和查看详情。
- 存储故障显示错误提示，不显示空档案。
- 原有管理、Bangumi 和备份能力不受影响。
- 全量测试、TypeScript、ESLint 和生产构建通过。

## 后续阶段
