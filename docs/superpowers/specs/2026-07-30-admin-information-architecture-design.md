# 管理后台信息架构设计

## 目标

把当前同页堆叠的记录列表、录入表单和备份工具拆成三个明确工作区，降低日常管理的视觉负担和操作路径长度，同时保持现有数据、API、Bangumi 与备份行为不变。

## 现状问题

- 搜索、添加、备份和记录列表共享一条 `max-w-2xl` 窄列，主次关系不清。
- 备份管理器在每次进入后台时立即挂载并请求历史版本，即使用户只想编辑记录。
- “添加”只是列表上方的临时展开块，编辑、取消和返回列表之间缺少稳定位置感。
- 记录列表限定 500px 内部滚动，页面本身与列表形成双重滚动。
- 页面标题栏同时承担搜索、添加和退出，移动端拥挤。

## 信息架构

管理页继续使用 `/admin` 单路由，内部提供三个互斥工作区：

1. **记录**
   - 默认工作区。
   - 显示记录总数、搜索框、添加主按钮和完整记录列表。
   - 编辑记录时切换到“添加记录”工作区并载入当前数据。
2. **添加记录**
   - 新增时默认进入 Bangumi 搜索。
   - 可切换手动填写。
   - 选择 Bangumi 条目后预填，标签仍由管理员点击确认。
   - 保存或取消后回到“记录”。
3. **备份恢复**
   - 进入工作区时才挂载 `BackupManager` 并读取历史版本。
   - 显示当前记录数、导出、导入、历史版本和恢复流程。
   - 恢复或导入后刷新共享记录数据。

## 页面结构

- 顶部：后台标题、简短说明、退出按钮。
- 次级导航：三个 `role="tab"` 按钮，展示当前工作区。
- 内容区：单个 `role="tabpanel"`。
- 桌面最大宽度扩大到适合列表和表单的 `max-w-5xl`。
- 移动端导航保持三等分，标题栏不再放搜索框。

## 状态与行为

- `AdminSection = "records" | "entry" | "backups"`。
- `section` 只管理工作区；不引入全局状态库。
- 切换到新增工作区时重置编辑对象、Bangumi 预填和录入模式。
- 点击编辑时设置编辑对象并进入录入工作区。
- 保存成功后刷新列表并返回记录工作区。
- 取消新增或编辑后返回记录工作区。
- 备份工作区卸载时保持服务端数据不变；再次进入可重新读取最新历史。
- 不改变登录、退出、写接口、备份接口或 Bangumi 接口。

## 组件边界

- 新建 `components/admin/admin-section-nav.tsx`：只负责工作区导航。
- `app/admin/page.tsx`：继续拥有数据请求、保存、删除和工作区协调。
- 复用 `AnimeList`、`AnimeForm`、`BangumiSearch`、`BackupManager`。
- `AnimeList` 取消固定 500px 内部滚动，使用页面自然滚动。
- `BackupManager` 增加非折叠展示模式，供独立备份工作区使用。

## 错误与空状态

- 保持现有保存、删除、导入、恢复错误行为。
- 空记录页同时提供“添加第一条记录”主入口。
- 搜索无结果时保留清晰提示和清除搜索入口。
- 更完整的统一错误模型属于下一阶段“组件与安全边界整理”。

## 不在本阶段

- 不拆分 `/admin` 子路由。
- 不改变认证、CSRF、限流或 API 校验。
- 不改变存储、备份格式和 Bangumi 数据映射。
- 不建立完整视觉令牌系统；视觉规范留到第四阶段。

## 验收标准

- 首次进入后台只显示记录工作区，且不请求备份 API。
- 三个工作区不会同时显示。
- 新增、编辑、保存、取消都能落在正确工作区。
- 进入备份工作区后才读取历史版本。
- 桌面与移动端均没有双重列表滚动。
- 现有 Bangumi、记录 CRUD 和备份测试继续通过。
