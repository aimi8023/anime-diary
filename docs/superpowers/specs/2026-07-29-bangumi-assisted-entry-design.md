# Bangumi 辅助录入设计

日期：2026-07-29

## 背景

Anime Diary 当前通过管理页手动录入标题、季度、封面、话数、标签、个人评分和短评。站点定位是“个人长期使用、公开只读展示、仅站长管理”，不考虑多人账户或双向同步。

手动从 Bangumi 查找并复制资料是当前最直接的使用痛点。本阶段接入 Bangumi API 作为后台资料搜索器：站长按需搜索并选择条目，系统预填表单，站长确认和修改后才保存到自己的存储。

## 目标

- 按标题搜索 Bangumi 动画条目，最多展示 8 个匹配结果。
- 选择条目后预填标题、原始标题、封面、首播日期、季度和话数。
- 将 Bangumi 标签显示为候选标签，由站长点击选择，不自动全选。
- 保存 Bangumi 条目 ID 和来源链接，用于溯源和精确重复检测。
- Bangumi 不可用时，已有记录与手动录入继续正常工作。
- 公开首页只读取本地快照，不依赖 Bangumi 实时响应。

## 非目标

- 不导入 Bangumi 全量条目。
- 不同步 Bangumi 收藏或观看进度。
- 不把个人评分、短评或标签写回 Bangumi。
- 不自动刷新或覆盖已经保存的本地资料。
- 不增加多用户、注册或多租户能力。

## 总体架构

管理页不直接访问 Bangumi。新增两个受管理员 Cookie 保护的站内接口，由服务端代理第三方请求：

```text
管理页
  ├─ GET /api/bangumi/search?q=<keyword>
  │    └─ POST https://api.bgm.tv/v0/search/subjects
  └─ GET /api/bangumi/subjects/:id
       └─ GET https://api.bgm.tv/v0/subjects/:id
```

新增独立适配层，避免 Bangumi 实验性搜索接口的变化扩散到页面与存储代码：

```text
lib/bangumi/
├── client.ts   # HTTP 请求、超时、User-Agent、可选 Bearer Token
├── mapper.ts   # 第三方数据到站内搜索结果/表单初始值的转换
└── types.ts    # 仅声明项目实际使用的 Bangumi 字段
```

`proxy.ts` 的匹配范围扩展到 `/api/bangumi/:path*`。未登录访问统一返回 `401`。

## 数据模型

`Anime` 与 `AnimeInput` 增加以下可选字段：

```ts
bangumiId?: number;
bangumiUrl?: string;
originalTitle?: string;
airDate?: string;
```

全部字段保持可选，以兼容已有记录，无需一次性迁移 `data/anime.json` 或 Redis 数据。

个人 `rating`、`comment` 与最终 `tags` 不从 Bangumi 强制写入。Bangumi 社区评分不映射到个人评分。

## 数据映射

选择条目后，详情接口返回统一的预填结构：

```ts
interface BangumiPrefill {
  bangumiId: number;
  bangumiUrl: string;
  title: string;
  originalTitle: string;
  cover: string;
  airDate: string;
  season: string;
  episodes: number;
  suggestedTags: string[];
}
```

映射规则：

- `title`：优先使用中文名 `name_cn`，为空时回退到原名 `name`。
- `originalTitle`：使用 `name`；若与 `title` 相同仍可保存，页面可决定是否展示。
- `cover`：按 `large`、`common`、`medium` 的顺序回退，无图时为空。
- `airDate`：使用合法的 `YYYY-MM-DD` 日期，否则为空。
- `season`：从合法首播日期计算；日期缺失时为空并由站长手动选择。
- `episodes`：使用正篇话数；缺失或非法时为 `0`。
- `suggestedTags`：按 Bangumi 返回顺序取前 12 个非空标签并去重，仅作为候选。
- `bangumiUrl`：规范化为 `https://bgm.tv/subject/{bangumiId}`。

季度换算沿用项目现有约定：

- 1–3 月：春
- 4–6 月：夏
- 7–9 月：秋
- 10–12 月：冬

## 管理页交互

现有添加区域顶部增加两个入口：

```text
[从 Bangumi 搜索] [手动填写]
```

默认进入 Bangumi 搜索，手动填写始终可用。

### 搜索

1. 站长输入标题，点击搜索或按 Enter。
2. 搜索按钮在请求期间禁用，避免重复提交。
3. 结果最多显示 8 项，每项包含封面、中文名、原名、首播日期和话数。
4. 已存在相同 `bangumiId` 的结果显示“已收录”。
5. 无结果、超时、限流或上游异常仅影响搜索区域，并提供“改为手动填写”。

不使用每次输入立即请求的实时搜索，以减少第三方请求和结果跳动。

### 选择与预填

1. 点击未收录结果后请求完整详情。
2. 成功后收起搜索结果，并将数据写入现有表单的可编辑初始值。
3. 表单顶部显示“资料来自 Bangumi”和来源链接。
4. 自动填写的任何字段都允许修改，最终以站长提交的数据为准。
5. 如果条目已收录，不创建副本，而是提示并允许打开已有记录编辑。

### 标签

标签区分为：

- 已选择标签：最终保存，支持删除。
- Bangumi 推荐标签：未选候选按钮，点击后加入已选择标签。
- 手动标签：继续支持输入个人标签。

标签比较在去除首尾空白后进行，完全相同的标签不重复添加。选中的候选标签从推荐区隐藏。

## 站内 API

### `GET /api/bangumi/search`

查询参数：

- `q`：必填，去除首尾空白后长度为 1–100 个字符。

行为：

- 仅搜索动画类型。
- 按匹配程度排序。
- 最多返回 8 项。
- 返回精简后的站内结构，不透传 Bangumi 原始响应。
- 根据本地记录的 `bangumiId` 标记 `alreadyAdded`，并在存在时返回本地记录 ID。

错误：

- 空或非法查询：`400`
- 未登录：`401`
- Bangumi 超时：`504`
- Bangumi 限流：`503`
- 其他上游错误：`502`

### `GET /api/bangumi/subjects/:id`

行为：

- 校验 ID 为正整数。
- 获取完整条目并转换为 `BangumiPrefill`。
- 条目不存在返回 `404`。
- 上游异常采用与搜索接口相同的错误映射。

## 保存与重复检测

现有 `POST /api/anime` 增加服务端重复检测：

- 当请求包含 `bangumiId` 且该 ID 已存在时，返回 `409` 和已有记录 ID。
- 没有 `bangumiId` 的旧数据不按标题自动判重，避免同名误判。
- 更新记录时允许保留自己的 `bangumiId`，但不允许改为另一条已被占用的 `bangumiId`。

存储接口增加按 `bangumiId` 查询能力，JSON 和 Redis 实现保持相同行为。当前数据量很小，可先在线性列表中查询，不增加索引或新数据库。

## 安全与配置

- Bangumi 请求只从服务端发出。
- 设置项目专属 `User-Agent`，格式中包含开发者标识与项目名称。
- `BANGUMI_ACCESS_TOKEN` 作为服务端环境变量；协议允许匿名读取时可选，生产部署推荐配置。
- Token 不发送给浏览器，不写入日志或 API 错误响应。
- 请求设置超时，并限制关键词长度与返回数量。
- 公开访客不能访问 `/api/bangumi/*`。

## 缓存与可用性

- 搜索结果可做约 5 分钟的尽力缓存，减少短时间重复搜索。
- 条目详情可缓存约 1 小时；保存后仍是本地快照。
- 缓存失效或 serverless 实例重启只影响性能，不影响正确性。
- 缓存实现不得成为第一阶段的独立基础设施依赖。

## 错误处理

- 管理页保留搜索关键词和已填写表单内容。
- 搜索失败不会清空表单，也不会影响手动模式。
- 详情字段缺失时以空值或 `0` 降级，由站长补充。
- 对外显示简短中文提示；服务端日志记录状态码和请求阶段，但不记录 Token 或完整第三方响应。
- 保存时遇到 `409`，页面提示打开已有记录编辑。

## 测试与验收

### 单元测试

- 中文名缺失时回退到原名。
- 封面按指定优先级回退。
- 季度换算覆盖 3/4、6/7、9/10 月边界。
- 非法或缺失日期不生成错误季度。
- 标签去空、去重和最多 12 个候选。
- 缺失话数回退为 `0`。

### API 测试

- 未登录访问 Bangumi 代理接口返回 `401`。
- 空关键词返回 `400`。
- 搜索仅返回动画且不超过 8 项。
- 超时、限流、上游错误映射到约定状态码。
- 重复 `bangumiId` 创建返回 `409`。
- 更新时正确处理 Bangumi ID 冲突。

第三方请求在自动化测试中使用 mock，不依赖真实 Bangumi 服务。

### 交互验收

- 完成一次“搜索 → 选择 → 选择推荐标签 → 修改个人评分和短评 → 保存”。
- 已收录条目可识别并打开原记录。
- Bangumi 不可用时可切换手动录入。
- 桌面端和移动端均能完成搜索与保存。
- 最终运行 lint、类型检查、自动化测试和生产构建。

## 后续阶段

完成辅助录入后，再分别设计和实施：

1. 自动备份、恢复与数据导入。
2. 更强的组合筛选、排序和回顾统计。
3. 移动端交互与视觉统一。

这些阶段不与本次 Bangumi 接入捆绑，避免同时修改多个独立子系统。
